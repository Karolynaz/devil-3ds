# Devil-3Ds 3.01 test build

## Changes

- The pinned ZeroTier Binder skipped `getifaddrs()` on 3DS but left
  `interfacesEnumerated` true. Its address set stayed empty, preventing even
  wildcard UDP/TCP bindings. The adapter now uses IPv4 wildcard bindings;
  physical IPv6 is excluded while the virtual game network retains IPv6.
- Multiplayer waits for the node to be online and receive its virtual network
  address. A cancellable 45-second limit and controller error reporting replace
  advancing into an unconnected lobby. Public-game requests reset on every
  lobby entry; a failed request cannot display Loading indefinitely.
- Native keyboard OK now submits the active form, and Cancel navigates back.
  Password/name byte limits are enforced before submission. A newly queued
  keyboard waits until its menu has rendered and completed its fade.
- Name/password/game-ID fields are wider. Text padding uses the actual native
  pentagram width. Short headings measure the correct top/bottom pixel scale
  and fall back to native smaller fonts when necessary. Hero stat labels use
  the small font, avoiding overlap with the portrait in Lithuanian.
- Update checks initialize and validate the `ssl:C` random-data service used by
  devkitPro's mbedTLS entropy source. The old code never initialized it. TLS 1.2,
  HTTP/1.1 and IPv4 are selected explicitly; certificate verification remains
  enabled and the bundled CA certificate file is retained.
- ZeroTier callback writes and foreground peer-event queries share a lock.
- `PORT_VERSION` is **3.01**, visible in Update alongside the build identifier.
  Engine and multiplayer protocol versions retain their existing values.

The portlibs entropy source is documented in the official
[mbedTLS package patch](https://github.com/devkitPro/pacman-packages/blob/master/3ds/mbedtls/mbedtls-2.28.8.patch).

## Verification

Production worker, native keyboard queue and pinned Binder method are exercised
with service/socket mocks under ASan and UBSan. Existing receive, UI pixel,
settings and multiline/fade regression checks also pass. Cross-compilation and
bundled package verification run through the Nintendo 3DS workflow.

No emulator or console was run by Codex. Actual TLS negotiation, public-game
responses and creation/join must be confirmed on the user's devices. This is a
local test package, not a GitHub Release.

## Device checks

1. Verify Update shows 3.01, then Check for updates with Wi-Fi connected.
2. Select Multiplayer and allow the ZeroTier connection screen to finish.
   Cancel should return to the menu; a failure should provide a bounded error.
3. Confirm Lithuanian hero headings, stat labels, names and password fields fit.
4. Create a private game; keyboard OK should continue without pressing A again.
5. Return and create a public game; compare discovery with a compatible desktop
   DevilutionX build. Join that game from the other device.
6. Repeat with Hellfire enabled on both ends if testing a Hellfire session.
